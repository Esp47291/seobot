# Офферы

## Заказчику

**Пилот 2 недели:** 1 точка, 1–2 площадки, фиксированный объём *принятых* работ (число согласовать, не обещать рейтинг), отчёт скринами/таблицей, слоты только в близких городах.

Цена пилота: **нет факта** → считать от P_ex * 1.25 + модерация + запас (см. UNIT_ECONOMICS). Не называть ₽ в холодном касании, пока нет прайса.

Не оффер: «выведем в топ», «50 пятёрок», готовый текст отзыва, «партнёр Яндекса/Google».

После `#lead` оффер **включается только если** квалификация = берём (таблица ниже). Иначе — скрипт 16, счёт не выставлять.

Цена — не рычаг квалификации: серый запрос с любой P_c не даёт CM1 (ToS, C_mod, неверный supply). «Дешевле, но без визита» ≠ пилот. Пилот = take + P ≥ P_c_min после UNIT-01.

## Квалификация пилота (стык с формой)

Форма даёт имя / город / Telegram / площадки. Это ещё не пилот. Пилот = Q3 процесс + Q4 честный темп + город, где можно дать слот.

| Сигнал с заявки / чата | Оффер | Следующий шаг |
|---|---|---|
| Город + точка + «разберите процесс» | пилот 14 дней | Q4 темп → цена после UNIT_01 |
| Площадки пустые | всё ещё пилот | спросить Яндекс / 2ГИС / Google |
| «Нужен рейтинг / 50 пятёрок» | нет | скрипт 8 или 16 |
| «Пришлите тексты отзывов» | нет | скрипт 15 |
| «Это же накрутка? Нам надо чтобы работало» | пилот только если принимают границу ToS | скрипт 14; иначе 16 |
| Город без исполнителей | **ASSUMPTION** не обещать срок | либо отложить слоты, либо отказ «пока нет людей рядом» |

Факт supply по городам: выгрузка `TaskItem.venue_city` с прода. Пока нет списка — не писать «работаем в N городах».

## Исполнителю

Понятные слоты, цена на карточке, проверка, баланс, вывод от W_min (default 20 ₽ — проверить settings в проде).  
Реферал — доля с **принятых** заданий.
