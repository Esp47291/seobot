# Антифрод-сигналы (детекция, не обход)

Для админ-очереди. Без инструкций, как обойти. Цель: меньше ложных банов, быстрее ручная проверка новичков.

## Сигналы (слой 1 — уже почти в данных)

| Сигнал | Зачем | Где смотреть | Действие |
|---|---|---|---|
| Слишком быстрый submit | Нереалистичный визит+публикация | submitted_at − attempt.created_at | Не автобан: в топ очереди |
| Пачка заявок с одного паттерна | Координация | несколько user_id, один platform+venue за минуты | Общий просмотр |
| Повтор exhausted → second-acc сразу | Давление на лимиты | SecondAccountReview после completed той же платформы | Строже смотреть скрин |
| Реферальный веер | Нагон пустышек | много referral_join, 0 completed у referees | Не платить за вход (уже так) |
| Смена реквизитов перед выводом | Перехват | payout_requisites vs wd.requisites | Сверить с историей |
| Отказы подряд | Либо непонимание ТЗ, либо мусор | N rejected подряд | Сначала улучшение copy, не бан |
| Новый аккаунт + сразу вывод крупный | Риск | registered_at vs first wd | Hold первой выплаты (гипотеза 24ч, как у гиг-рынков) |

## Сигналы (слой 2 — нет в коде)

- Повтор одного и того же file_id / похожие кадры между user_id
- Город точки ≫ далеко от типичных городов пользователя (прокси-паттерн) — **осторожно**: это эвристика, не доказательство
- Device/Telegram account age — Telegram не отдаёт надёжно

Не строить продукт на «как обойти гео-фильтр площадки». Гео в UX — про качество и честный визит.

## Операционка

- Новичок (0 completed) — всегда ручная очередь (TechVinta).
- Каждое fail: reason_code + сообщение юзеру (audit, gruv.ai).
- 3-strike: после N reject — мягкий лимит новых take, не молчаливый shadowban без текста.
