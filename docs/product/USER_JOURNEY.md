# Job Inside — пользовательские пути

Каждый шаг: цель → экран → событие → friction → улучшение.  
Код: `origin/patch-15`, если не указано иное. События — целевые имена из `docs/analytics/EVENT_TAXONOMY.md` (в коде их ещё нет).

## 1. Исполнитель

### 1.1 Первый вход

| | |
|---|---|
| Цель | Понять, что это за бот, и не заблокировать |
| Экран | Rules middleware → welcome + reply-меню |
| Событие | `start` `{is_new:true, has_ref:bool}` → `rules_accept` → `onboarding_done` |
| Friction | Длинные правила, прокси, нет выбора роли. Реферал сгорает, если человек уже заходил без ссылки |
| Улучшение | 2 кнопки роли; правила после выбора «задания»; реферал фиксировать и на «первом completed», не только на insert user |

### 1.2 Выбор слота

| | |
|---|---|
| Цель | Найти работу в своём городе на понятной площадке |
| Экран | Gate канала (self-confirm) → список городов заведений → платформы → карточка (цена, сфера) |
| Событие | `channel_gate_ok` · `venue_city_select` `{city}` · `platform_select` · `task_view` `{task_id, platform, price}` |
| Friction | Город — организации, не «мой город»; карточка без инструкции; «второй аккаунт» рядом с исчерпанием слотов выглядит как обход |
| Улучшение | Подпись «город точки, берите ближние»; превью инструкции; second-acc — отдельный честный сценарий «доп. проверка», не CTA на исчерпании |

### 1.3 Взять и доказать

| | |
|---|---|
| Цель | Понять ТЗ, сделать работу, сдать доказательство |
| Экран | «Начать» → скрин аккаунта → ожидание → approved → скрин отзыва (реквизиты из профиля) |
| Событие | `task_take` · `proof_submit` `{kind:account\|review}` |
| Friction | Две ступени неочевидны до входа. Реквизиты могут всплыть на втором скрине. FSM в памяти — рестарт убивает шаг |
| Улучшение | Чеклист из 3 пунктов на старте; реквизиты заранее; persist FSM |

### 1.4 Модерация и деньги

| | |
|---|---|
| Цель | Узнать исход, увидеть баланс, вывести |
| Экран | «Скриншот получен. Ожидайте» → ЛС approve/reject → кабинет → вывод сумма/реквизиты |
| Событие | `proof_submit` (старт ожидания) → `moderation_pass` / `moderation_fail` `{stage}` · `balance_update` (у менеджерского слота — только после `mgr:outpay`, не после pass) · `withdraw_request` · `withdraw_paid` |
| Friction | Нет id, нет стадии, нет ETA. Хаб админа занижает допуск — нельзя честно сказать «вы в очереди». Отказ без фикса. Вывод — чёрный ящик. Напоминание «можно снова» есть — плюс |
| Улучшение | UX-03: id + именованная стадия + «обычно в рабочие часы»; не минуты и не «N-й». Отказ = причина + следующее действие. Статус заявки на вывод (UX-05). Не «оплачен», пока `balance_credited` |

#### 1.4a Ожидание после скрина (H1 круг 2)

Отдельный шаг: человек уже сделал работу и сидит в темноте. Это не «ещё одно поле copy», это место оттока F2 (submit → pass).

| | |
|---|---|
| Цель | Понять, что сдача жива, ничего не сломалось, и что делать (почти всегда — ждать) |
| Экран сейчас | Три почти одинаковых «ожидайте» без id (профиль / отзыв / 2-й акк). Кабинет: «⏸ на проверке» только для `review_submitted`; допуск = сырой `Статус: waiting_approval` |
| Событие | Уже есть якорь `proof_submit`. Отдельный `wait_ack` не нужен в Phase 1. Тикет в поддержку до fallback — шум, не метрика успеха |
| Friction | Одинаковый текст на S2 и S3. Повтор скрина не объяснён. Нет fallback «когда писать». Исполнитель может решить, что бот завис, и уйти |
| Улучшение | Спека в `BOT_UX_VISION.md` UX-03. Карточка до take (UX-02) заранее говорит «проверка вручную, рабочие часы» — ожидание не засада |

| Шаг после submit | Что человек думает | Честный ответ | Не отвечать |
|---|---|---|---|
| Только что сдал | Дошло ли? | «Скрин получил, заявка #{id}» | молчание, только ✅ |
| Через час | Смотрят? | Стадия (профиль vs работа). Человек, не «система» | «уже смотрим», позиция в хабе |
| Вечер / выходной | Забыли? | «обычно в рабочие часы» | «до 22:00 сегодня» без settings |
| Следующий рабочий день | Писать в поддержку? | Да, fallback. Не раньше | «напишите через 5 минут» |

### 1.5 Реферал и повтор

| | |
|---|---|
| Цель | Позвать людей / взять следующее без боли |
| Экран | Рефералка (ссылка + 20/5 + сумма) · reminder scheduler |
| Событие | `referral_share` · `referral_join` · `referral_reward` · `repeat_reminder_sent` |
| Friction | Нет числа «оплаченных» рефералов. Повтор — полный wizard город→платформа |
| Улучшение | Qualified count. «Ещё в {city} / {platform}» одной кнопкой |

## 2. Заказчик / менеджер

Заказчик-внешний в боте **не выделен**. Менеджер = `MANAGER_IDS`: создаёт задания, смотрит статистику, шлёт личную рассылку, закрывает выводы и исходящие оплаты.

### 2.1 Вход менеджера

| | |
|---|---|
| Цель | Попасть в панель, не в меню исполнителя |
| Экран | Тот же /start + `/manager` |
| Событие | `staff_open` `{role:manager}` |
| Friction | Нет онбординга «я заказчик». Бизнес с улицы жмёт «Приступить к заданию» |
| Улучшение | Ветка /start «Бизнес» → бриф в поддержку. Менеджеру — pinned «сегодня: очередь / слоты / выводы» |

### 2.2 Создать задание

| | |
|---|---|
| Цель | Опубликовать слот: площадка, цена, город, сфера, инструкция, тексты, лимит в день, ссылка |
| Экран | FSM 8 шагов (platform→…→venue_link), опционально prebuilt тексты/фото |
| Событие | `task_create` `{platform, price, daily_cap, has_prebuilt}` |
| Friction | Длинный мастер, MemoryStorage, цена ниже минимума платформы — нужна явная ошибка (проверить в UI) |
| Улучшение | Черновик в БД с «продолжить»; превью карточки как у исполнителя до публикации |

### 2.3 Модерация чужих сдач

| | |
|---|---|
| Цель | Принять или отклонить доказательство |
| Экран | Очереди admin/manager + scheduler-напоминание |
| Событие | `moderation_pass` / `moderation_fail` `{actor:manager}` |
| Friction | Нет видимого SLA для исполнителя; риск очереди вечером |
| Улучшение | Сортировка: новички и «висят > SLA» сверху. Шаблон причин отказа |

### 2.4 Деньги исполнителям

| | |
|---|---|
| Цель | Не копить баланс без выплаты |
| Экран | Заявки на вывод; `outpay` после работы по заданиям менеджера |
| Событие | `withdraw_paid` `{actor:manager}` |
| Friction | Ручной контур, два места (вывод vs исходящая оплата) |
| Улучшение | Один inbox «деньги»: выводы + невыплаченные completed |

### 2.5 Будущий заказчик (сайта нет)

| | |
|---|---|
| Цель | Понять оффер и оставить заявку |
| Экран | Пока только Telegram support / менеджер |
| Событие | `biz_lead` `{source}` |
| Friction | Нет лендинга, нет формы, нет прайса |
| Улучшение | Сайт: 1 оффер + CTA. В боте — короткая форма: город, площадки, объём/мес |

## 3. Админ

### 3.1 Пульт

| | |
|---|---|
| Цель | Здоровье системы за 60 секунд |
| Экран | `/admin`, `/status`, analytics hub, moderation hub, export CSV |
| Событие | `admin_dashboard_view` (внутреннее) |
| Friction | Метрики — срезы сущностей, не воронка шагов. Нет «где отваливаются сегодня» |
| Улучшение | Daily: новые / взяли / сдали / pass% / очередь старше SLA / выводы pending / сумма |

### 3.2 Снабжение и настройки

| | |
|---|---|
| Цель | Задания, мин. цены, welcome, min withdraw, рассылка |
| Экран | Создание заданий (как у менеджера) + settings + broadcast all/personal |
| Событие | `broadcast_sent` `{mode:all\|personal}` → позже `broadcast_click` |
| Friction | Массовая рассылка без сегмента по городу = раздражение и блоки |
| Улучшение | Сегмент город/платформа/«есть незавершённая попытка». Opt-out |

### 3.3 Риск и люди

| | |
|---|---|
| Цель | Блок, правки баланса, second-account очередь |
| Экран | Users manage, secacc queue, balance change |
| Событие | `user_block` · `secacc_decision` · `balance_adjust` |
| Friction | Антифрод — глаза, не сигналы |
| Улучшение | См. `ANTI_FRAUD_SIGNALS.md`: скорость сдачи, повторы скринов, пачки рефералов |

## Воронка исполнителя (для Miro и аналитики)

```
start → rules_accept → onboarding_done
  → task_view → task_take
  → proof_submit(account) → moderation_pass(account)
  → proof_submit(review) → moderation_pass(review)
  → balance_update → withdraw_request → withdraw_paid
```

Формулы — `docs/analytics/FUNNELS.md`. Факт конверсий: **нет в репо** → считать из БД attempts + users после инструментации.
