# Бизнес-модель

Кто платит: **локальный бизнес / агентство** за организацию слотов и принятые работы.  
Исполнитель — cost (выплата + реферал), не источник выручки.

Сайта нет: продажи = Telegram + исходящие касания.

## Деньги

| Поток | Направление | Факт в коде |
|---|---|---|
| Оплата заказчика | → Job Inside | сущности «счёт / заказ» нет. Менеджер создаёт TaskItem с price = выплата исполнителю |
| Выплата исполнителю | ← баланс ← price задания | `grant_task_completion_rewards` |
| Реферал L1/L2 | ← 20% + 5% от price | поверх выплаты |
| Вывод | ручной перевод по заявке | `WithdrawalRequest` |

Маржа заказчика **не смоделирована в БД**. Нужно: цена для клиента ≥ price + ref_worst(25%) + модерация + касса + риск отказа площадки.

Это **managed service со слотами**, не комиссионный маркетплейс: take rate из учебника здесь нельзя посчитать — нет GMV. Путать `task.price` с «оборотом» нельзя: это COGS supply.

## Юнит (формула, не цифра P&L)

```
contribution = P_client − P_executor − P_ref − C_moderation − C_pay − C_acq
```

- `P_executor` = `task.price`  
- `P_ref` = 0 … 0.25 * price (если есть L1 и L2)  
- `C_moderation` = минуты × ставка — ASSUMPTION, замерить  
- `C_pay` = комиссия перевода — ASSUMPTION  
- `C_acq` = стоимость лида / число принятых единиц — ASSUMPTION  

Дефолты мин. цен в settings: Яндекс 130 / Google 35 / 2ГИС 12 — **пол исполнителя**, не прайс B2B.

## Кто создаёт юнит (take), кто его запрещает (no_take)

Юнит появляется только после квалификации **берём** (H4) **и** появления P_c (UNIT-01).  
`no_take` — не «лид, который ещё поторгуемся»: серый объём повышает C_mod, портит supply и не даёт CM1, даже если клиент готов платить.

Не заполнять простой исполнителей серыми слотами. Простой — сигнал держать кассу и UX (SLA, статусы), не сигнал снижать планку ToS.

Деньги клиента и деньги исполнителя разведены: `mgr_outpay` создаёт баланс до того, как в системе вообще есть счёт. Кассовый разрыв — часть модели, пока нет сущности заказа. Не масштабировать take, пока WD pending растёт без входящих.

## Риски модели

Ручные выплаты + MemoryStorage + нет event-воронки = слепая операционка.  
Репутация площадок: позиционирование только как качественный локальный сервис.  
Headline «наценка к P_ex» без ref и C_ops = ложная маржа. Пол 2ГИС/Google как B2B-SKU до замера C_mod = почти наверняка CM1 < 0 (ASSUMPTION, см. UNIT table).
