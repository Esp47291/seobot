## Severity (не один SLA на всё)

| Sev | Триггер | Действие | Гипотеза срока |
|---|---|---|---|
| S0 | Претензия площадки / юрист / клиент просит «чтобы не заметили» | Стоп новых слотов и take. Разбор playbook. Не спорить в публичном copy | сразу |
| S1 | WD pending и P_c получен | Платить по шлюзу inbox | 24ч рабочих ASSUMPTION |
| S2 | `review_submitted` без решения | Разбор с конца (ASC по `submitted_at`) | 24ч ASSUMPTION |
| S3 | Допуск без решения | Не путать с отзывом; хаб занижает | 48ч ASSUMPTION |
| S4 | Первый WD / смена реквизитов | Hold, сверка | hold, не ускорять |
| S5 | Mgr unpaid | Ждать P_c, не кредитовать баланс | до входящего, не «до вчера» |

Сроки 24/48ч — гипотеза, пока нет медианы с 20 строк `updated_at−submitted_at`. Не обещать «5 минут».

## Playbook инцидентов

Не публиковать в канал и не писать клиенту «схемы». Staff-only.

### I1. Претензия площадки или «нас сняли отзывы»

1. Стоп: новые `TaskItem` по этой площадке/точке, broadcast, напоминания «можно снова».  
2. Не удалять доказательства: attempts + file_id остаются для разбора (срок хранения — назначить, P1 privacy).  
3. Клиенту: процесс останавливаем, рейтинг не гарантировали, возврат/заморозка — по договору (P_c в БД нет → решать вручную).  
4. Исполнителям в полёте: честный статус «проверка площадки, слот на паузе», не «пишите другой текст».  
5. Код: prebuilt больше не слать. Объём «загрузить слоты» = no_take, не скидка.

### I2. Касса: WD pending растёт, P_c не видно

1. Снять Q4 ₽ + Q5 ₽ (inbox SQL).  
2. Не `mark_paid` по нефондированному.  
3. Не outpay менеджерские completed «чтобы люди не ждали».  
4. Supply: честный ETA вывода, не молчание и не «сейчас отправим».  
5. Продажи: новые take только после UNIT-01 на этот объём.

### I3. После деплоя «бот забыл сдачу»

Симптом MemoryStorage: пользователь в скрине/выводе получил «не то состояние».  
1. Не повторный деплой «починить».  
2. Staff: найти attempt по user_id, не просить «пришлите скрин ещё раз» вслепую, если file_id уже в БД.  
3. Зафиксировать TECH-01 как причину. Следующий деплой — только в окно, когда Q1–Q4 пусты или после persist FSM.

### I4. Секрет в git / правила со ссылкой на прокси

1. Не вставлять URL в docs, PR, Miro, канал.  
2. Днём: вынести в env, ротировать, вычистить RULES (COPY-01).  
3. Считать скомпрометированным всё, что уже в истории git — ротация, не «надеемся не видели».
